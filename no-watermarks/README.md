# no-watermarks

Deterministically strips AI provenance marks from what the agent produces,
whichever provider's model is behind it: invisible-Unicode carriers in replies
and written files, and agent attribution (Claude Code, Codex, Cursor, Copilot,
Devin, Amp, Gemini, Jules, aider, OpenCode, Crush, Kiro, Junie, Qwen, ...) in
commit messages and PR/issue bodies.

Modeled on [guillaumemeyer/watermarks-remover](https://github.com/guillaumemeyer/watermarks-remover)
(MIT) and on [`../no-em-dash`](../no-em-dash). That project's key point
applies here too: a skill or prompt is an instruction the model may skip, and
the model is the thing producing the marks, while a hook runs on every
matching event whether the model cooperates or not. This extension is only the
hook half. There is no prompt layer, because the model doesn't choose to emit
these characters, so there's nothing useful to instruct.

## What it strips

**Invisible Unicode** (`unicode.ts`, a port of upstream's
`service/scripts/text_unicode.py`, its deterministic "Layer A"):

| Kind | Examples |
| --- | --- |
| `zero_width` | ZWSP, ZWNJ, ZWJ, word joiner, BOM |
| `bidi` | LRO/RLO overrides, unpaired LRE/RLE/PDF |
| `tag_chars` | U+E0001..E007F ("ASCII smuggling") |
| `variation_selector` | VS1-16, VS17-256 when not attached to anything |
| `noncharacter`, `reserved_ignorable` | U+FDD0..FDEF, U+nFFFE/FFFF, U+2065, ... |
| `private_use` | PUA code points (replies only, see below) |
| `format` | soft hyphen, invisible math operators, any other stray `Cf` |
| `space` | NBSP, NNBSP, thin/em/ideographic spaces, normalized to U+0020 |

The part that matters most is what it **keeps**. Upstream's context rules are
ported intact, since the same code points carry meaning in context: ZWJ inside
emoji sequences (family, heart-on-fire), VS16 after an emoji base, tag
characters inside a complete subdivision flag, ZWNJ/ZWJ between letters of a
joining script (Persian, Devanagari), LRM/RLM, isolates, and paired embeddings
in RTL text, CJK/Mongolian variation selectors, Khmer/Hangul fillers after
their own script, orthographic Arabic/Syriac `Cf` marks, and hieroglyph,
Duployan, or musical layout controls next to their own script.

None of these rules assume a provider: they target character classes, not a
vendor's scheme.

**Agent attribution** (`attribution.ts` + `vendors.ts`), the visible
watermark. Four generic rules:

| Rule | Examples |
| --- | --- |
| Identity trailers (`Co-authored-by`, `Signed-off-by`, `Assisted-by`, `Generated-by`, any `*-by`/`*-with`) whose identity is an agent | `Co-Authored-By: Claude <noreply@anthropic.com>`, `Co-authored-by: Cursor <cursoragent@cursor.com>`, `Generated-by: OpenAI Codex`, `Assisted-by: Crush:grok-4.6` |
| Agent metadata trailers | `Copilot-Session: ...`, `Amp-Thread-ID: https://ampcode.com/threads/...`, `Committed-By-Agent: codex` |
| "Generated with X" lines, any leading emoji | `🤖 Generated with [Claude Code](...)`, `💘 Generated with Crush`, `Generated by Mistral Vibe.` |
| Session-link lines in PR bodies | a bare Codex task URL, `Devin Session: https://app.devin.ai/...`, Jules' `*PR created automatically by Jules...*`, Cursor's `Open in Cursor` HTML footer |

**How identity is decided** (`isAgentIdentity`). The email decides when there
is one, because display names collide with humans:

- An agent-only domain (`aider.chat`, `ampcode.com`, `kiro.dev`, ...) is
  always an agent.
- A vendor domain with human employees (`openai.com`, `google.com`,
  `jetbrains.com`, ...) is an agent only if the local part is `noreply` or
  names an agent, or the display name does. So `Codex <codex@openai.com>` is
  removed and `Jane Doe <jane@openai.com>` stays.
- A GitHub noreply address depends on the login. The login must be an agent
  name (`Copilot`, `codex`), or a hyphenated login with an agent component
  plus a bot marker (`devin-ai-integration[bot]`, `claude-ai`,
  `junie-live-agent`). So `starofgodmayomi-droid` or `github-actions[bot]`
  stay.
- Any other domain is a human (`Claude Monet <claude@monet.fr>` stays).
- With no email, the name has to start with an agent name (`Co-authored-by:
  Amp`, `Assisted-by: pi:llama.cpp/...`).

Every rule matches a whole line only, and the blank lines before it are
removed with it. So prose like "generated with Claude's help" or "feat: support
files generated by Cursor" is left alone, and a remaining human trailer keeps
its blank-line separation (git needs it to parse the trailer block).

### Adding a provider

Edit `vendors.ts` only: add the agent name to `AGENT_NAMES` and its email
domain to `AGENT_ONLY_DOMAINS` or `VENDOR_DOMAINS`. Add an odd GitHub login to
`KNOWN_BOT_LOGINS`, or a session-page URL to `SESSION_URLS`. Then add the real
line to `AGENT_LINES` in `attribution.test.ts`.

### Where the patterns come from

Not guessed. Every format in `vendors.ts` and `AGENT_LINES` was pulled from
real commits and PR bodies with `gh search commits "<phrase>"` / `gh search
prs`, aggregated by line. That's how several non-obvious ones turned up:
`Committed-By-Agent: codex`, `Copilot-Session:`, `Amp-Thread-ID:`,
`Assisted-by: Crush:<model>`, `claude-ai@users.noreply.github.com`, and
`Assisted-by: pi:<model>` (pi itself). To find a new provider's format:

```sh
gh search commits '"Co-authored-by: <Tool>"' --limit 40 --json commit \
  --jq '.[].commit.message' | grep -iE '^[A-Za-z-]+-by:|generated' | sort | uniq -c | sort -rn
```

False-positive check: run over the 35,733 commit messages in `~/Work` (mostly
`qmk_firmware`, human-written), it changed 11, all genuine Cursor/Claude
trailers, and missed none.

## Where it applies

| Hook | Target | Unicode | Attribution |
| --- | --- | --- | --- |
| `message_end` | assistant `text` blocks, code included | yes (PUA stripped) | no |
| `tool_call` `write` | `content` | yes (PUA kept) | message paths only |
| `tool_call` `edit` | each `newText`, never `oldText` | yes (PUA kept) | message paths only |
| `tool_call` `bash` | `git commit/tag/notes/merge/revert`, `jj describe/commit/new`, `hg`/`sl commit`, `gh`/`glab` `pr/mr/issue/release/api` only | yes | yes |

Design choices behind that table:

- **`oldText` is never touched.** It has to match the file's existing bytes; a
  wrong one fails the edit visibly, which is safe. Same rule as
  `no-em-dash/escape-guard.ts`.
- **PUA is kept in files.** Nerd Font and Powerline icons live in the private
  use area, and a shell-prompt config full of them is legitimate.
- **Attribution in files: message paths only**: temp dirs (`/tmp`,
  `/var/folders`, `os.tmpdir()`), where PR bodies and commit messages get
  staged for `--body-file` / `-F`, and `.git/COMMIT_EDITMSG` / `MERGE_MSG` /
  `SQUASH_MSG` / `TAG_EDITMSG`. A README or changelog that documents these
  trailers, like this one, has to survive.
- **Bash: message commands only.** `rg '<ZWSP>'` or `rg 'Co-authored-by:
  Claude'` contains exactly what we'd strip, on purpose. Only commands that
  carry a message are cleaned.
- **Shell quotes only count at argument boundaries.** A line can start right
  after `-m "` or `body='`, and end at a closing quote followed by whitespace,
  `)`, `;`, `&`, `|`, or the end. An apostrophe in prose (`Here's`, `Claude
  Code's help`) is never treated as a quote. The trade-off: a watermark line
  that itself contains an apostrophe inside a single-quoted argument isn't
  matched. That fails safe (the line survives) rather than corrupting the
  command.
- **Tool results are never modified.** See `../secret-guard/` for why
  rewriting tool output is a trap.

When a tool call is modified, a UI notification says what was stripped and
from where (`no-watermarks: stripped 1 zero_width, 1 attribution line from
/tmp/pr.md`). Reply cleaning happens silently.

## Out of scope

- **Statistical (token-sampling) watermarks.** These live in word choice, not
  characters. Upstream handles them with a best-effort rewrite by a different
  model ("Layer B"). That isn't deterministic and doesn't belong in a hook.
- **File metadata** (C2PA, EXIF, XMP, document properties). The agent writes
  text through `write`/`edit`, so there's no binary metadata to strip.
- **Files written by other means** (`bash` redirects, scripts, `cp`).
- **Hosted agents that commit on their own** (Codex cloud, Devin, Jules,
  Copilot coding agent). They push from their own infrastructure, so pi never
  sees those commits. This covers the models pi drives, whatever the provider.

## Files

| File | Purpose |
| --- | --- |
| `index.ts` | Registers the `tool_call` and `message_end` hooks |
| `unicode.ts` | Pure logic, `cleanInvisibleUnicode(text, opts)` |
| `attribution.ts` | Pure logic, `stripAttribution`, `isAgentIdentity`, `isMessageCommand`, `isMessagePath` |
| `vendors.ts` | Provider registry: agent names, domains, bot logins, session URLs |
| `*.test.ts` | Tests for each |

Tests (and `unicode.ts`) use `\u200B`-style escapes, never literal invisible
characters: a literal written through pi would be stripped by this extension.

## Running the tests

```sh
cd ~/.pi/agent/extensions/no-watermarks
node --test *.test.ts
```

No dependencies; Node 22+ strips TypeScript types natively.

## Disabling

```sh
mv ~/.pi/agent/extensions/no-watermarks ~/.pi/agent/extensions/no-watermarks.disabled
```

then `/reload`.
